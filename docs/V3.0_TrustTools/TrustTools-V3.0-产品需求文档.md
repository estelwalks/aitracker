## 1. 项目概述

### 1.1 背景

AI 编码工具爆发式增长，个人开发者日常使用 3-5 种 AI 工具、安装 10-30 个 Skill。Token 消耗不可见、Skill 来源分散且存在安全风险、会话丢失无法恢复。TrustTools V3.0 提供 Token 追踪 + Skill 管理 + 安全检测 + Skill 市场对接 + 会话恢复，打造**个人 AI 主权**桌面工具。

### 1.2 定位声明

个人 AI 主权桌面工具，开箱即用，无需登录注册。把散落在各 AI 工具的 skills、token 消耗、会话记录，统一收回用户手里。

### 1.3 利益相关者

| 利益相关者          | 角色       | 关注点             | 影响力 |
| ------------------- | ---------- | ------------------ | ------ |
| 老板                | 决策者     | 差异化竞争力       | 高     |

## 2. 目标与成功标准

### 2.1 业务目标

1. **Token 用量透明化**：让用户看见 token 消耗和费用，打开即见首页大盘，按时间/Provider 下钻
2. **Skill 资产管理**：扫描本地 skill、数量统计、一键清理、一键同步到多个 AI 工具
3. **Skill 安全检测**：外部下载的 skill 拖进来，静态规则扫描，几秒出安全报告
4. **TrustTools Skill 同步**：打通 Web 端 Skill 库，桌面版直接搜索/下载/安装
5. **会话恢复**：扫描本地 AI 工具的会话记录，检测丢失或异常中断的会话，支持一键恢复

### 2.2 MVP 成功标准

- 安装后 2 分钟内看到自己的 token 消耗
- 覆盖 27 个 AI 工具的 token 解析（Claude Code、Codex CLI、Cursor、Kiro、Gemini CLI、OpenCode、OpenClaw、Every Code、Hermes Agent、GitHub Copilot、Kimi Code、oh-my-pi、CodeBuddy、WorkBuddy、Grok Build、Kilo CLI、Kilo Code、Antigravity、pi、Craft Agents、Roo Code、Zed Agent、Goose、Droid、Mimo Code、ZCode、AnythingLLM Desktop）
- 外部 skill → 拖入检测 → 出报告 < 30 秒
- 桌面版搜索 → 选中 → 安装到指定 agent < 15 秒
- 启动后自动扫描并发现可恢复会话 < 10 秒

## 3. 用户画像

### 3.1 画像 1：个人 AI 开发者（P0）

- **特征**：日常使用 3-5 个 AI 编码工具，安装了 10-30 个 skill
- **痛点**：不知道花了多少钱、skill 太多不知道哪些没用、下载 skill 怕有安全问题、会话丢失找不回来
- **目标**：一个地方看清 token 消耗、管理 skill 资产、下载 skill 前扫一下、找回丢失会话

### 3.2 画像 2：AI 重度用户（P0）

- **特征**：Web + CLI + IDE 多端使用 AI，skill 来源分散
- **痛点**：各工具的 skill 散落在不同目录，无法统一管理
- **目标**：一个界面管理所有 agent 的 skill、从 TrustTools Web 库一键安装

#### FR-001: [MUST] 全页面时间区间切换与数据联动

**描述：** 用户在首页可以选择不同的统计时间区间。选择后，页面内所有指标卡片、图表、明细表同步更新为对应区间的数据。

**验收标准：**

- 提供 5 个时间选项：今日、近 7 天、近 30 天、全部、自定义
- "今日"按小时粒度展示（00:00~23:00 共 24 个数据点）
- "近 7 天"/"近 30 天"按日粒度展示
- "全部"展示所有历史数据（自首次采集起），按月粒度聚合
- "自定义"展开起止日期选择器，开始日期不得超过结束日期
- 切换区间后页面内所有模块同步刷新，不出现局部数据不同步的情况
- 顶部始终显示当前统计区间的文字标签和最近一次数据同步时间
- 切换区间不影响当前筛选条件、图例显隐状态

**关联史诗：** EPIC-01

---

#### FR-002: [MUST] 手动数据刷新

**描述：** 用户可手动触发重新采集和刷新数据。

**验收标准：**

- 操作栏提供刷新按钮，点击触发重新采集
- 刷新期间按钮进入不可重复点击的加载态，有视觉反馈
- 刷新完成后更新"最近同步"时间戳
- 刷新不影响当前时间区间、筛选条件、图例显隐状态

**关联史诗：** EPIC-01

#### FR-003: [MUST] KPI 核心指标卡片

**描述：** 页面顶部展示一组关键绩效指标卡片，让用户一眼看清 Token 消耗、费用和 Skill 概况。

**验收标准：**

- 核心指标卡片（第一行，4 张）：
  - **区间总费用**（含区间Token消耗总计换算的人民币金额）
  - **Token 消耗总量**（含环比变化，方向箭头 + 百分比，上涨/下降用不同颜色区分）
  - **缓存命中节省费用**（含缓存命中率百分比）
  - **本地 Skill 总数**（可点击跳转到 Skill 管理模块）
- 明细指标卡片（第二行，6 张）：
  - **总 Token / 总费用 / 输入 Token / 输出 Token / 缓存读 / 缓存写**
- 费用以人民币展示，精确到分
- Skill 数为 0 时仍可点击跳转
- 卡片在一行放不下时支持横向滑动查看，需有视觉提示告知用户有更多内容可滑动
- 卡片超出可视区域时显示页码导航和左右翻页按钮
- 滑动区域边缘有渐变遮罩提示
- 所有数值使用等宽数字字体保证对齐

**数据边界：**

- 费用计算基于：输入 Token × 输入单价 + 输出 Token × 输出单价 + 缓存读 Token × 缓存单价 + 缓存写 Token × 写入单价
- 环比 = (当前区间值 − 上个等长区间值) / 上个等长区间值 × 100%
- 无历史区间数据时环比显示为"−−"（含选择"全部"区间时，因无上一个等长区间）

**空状态：** 未检测到任何 AI 工具时，展示产品引导页，说明支持的 27 个工具列表，提供重新扫描入口。

**关联史诗：** EPIC-01

#### FR-004: [MUST] Token 消耗趋势图

**描述：** 以堆叠面积图或多序列折线图展示各 AI 工具的 Token 消耗随时间变化的趋势，支持图例交互。

**验收标准：**

- 支持堆叠面积图和多序列折线图两种渲染模式切换
- 数据序列按 AI 工具分列，每个工具使用固定的区分色
- X 轴标签根据时间区间自动适配格式（小时/日/周/月）
- Y 轴标注单位
- 图表上方展示统计摘要：区间合计、均值、峰值（含峰值时刻标签）、环比变化
- 图表显示均值参考线（虚线）
- 图表下方展示可交互图例：点击某个工具的图例可隐藏/显示其数据序列
- 隐藏序列后统计摘要仅计算可见序列
- 悬停数据点时显示浮层，列出该时刻各工具的 Token 值及各自占比，底部合计行显示总值
- 图例区域有提示文字说明交互方式

**数据边界：**

- 27 个 AI 工具：Claude Code、Codex CLI、Cursor、Kiro、Gemini CLI、OpenCode、OpenClaw、Every Code、Hermes Agent、GitHub Copilot、Kimi Code、oh-my-pi、CodeBuddy、WorkBuddy、Grok Build、Kilo CLI、Kilo Code、Antigravity、pi、Craft Agents、Roo Code、Zed Agent、Goose、Droid、Mimo Code、ZCode、AnythingLLM Desktop
- 数据序列名称使用工具名（非模型名）
- Token 单位使用 K/M 简写（1K = 1,000，1M = 1,000,000）
- 时间聚合粒度随区间变化：小时/日/周/月

**边缘场景：**

- 仅 1 个工具有数据时图表正常渲染
- 自定义日期范围为同一天时不报错
- 所有图例全部隐藏后界面不崩溃

**关联史诗：** EPIC-01

#### FR-005: [MUST] 上下文来源构成分析

**描述：** 以双栏面板展示 Token 消耗在不同 AI 工具和上下文维度上的分布构成，支持从工具到模型再到具体来源的多级下钻；层级结构、维度划分和展开逻辑由本项目定义。

**验收标准：**

- 左栏展示检测到的 AI 工具列表及其消耗占比，支持按工具名称搜索筛选
- "全部工具"选项聚合展示所有工具数据
- 选中工具后右侧展示该工具的维度分布与下钻明细
- 下钻行展示底层统计信息
- 顶部显示区间汇总（总 Token + 总费用）

**数据边界：**

- 占比 = 当前行 Token / 选中工具总 Token × 100%

**边缘场景：**

- 模型列表或实体列表为空时显示空数据提示
- 选中工具后切换到某维度但该工具无对应实体数据时列表为空，不报错

**关联史诗：** EPIC-01

#### FR-006: [SHOULD] 消耗时段热力图

**描述：** 以 7 行 × 24 列热力图展示一周内各时段的 Token 消耗密集程度，帮助用户发现使用高峰期。

**验收标准：**

- 7 行对应周一至周日（左侧标注星期简称），24 列对应 0~23 时（顶部每 3 小时标注刻度）
- 格子颜色深浅映射 Token 消耗量，从表面色渐变到品牌色
- 支持周偏移导航：左右箭头切换查看历史各周数据
- 当前周之后的时间不可查看
- 悬停格子时显示详细浮层：星期 + 时间段、Token 数、费用、会话数、主力模型
- 底部显示渐变色阶图例（少 → 多）
- 全部数据为 0 时格子颜色统一，不崩溃
- 小屏下提供横向滚动能力

**数据边界：**

- 强度基于 Token 绝对量计算色阶
- 168 个格子（7×24），每个格子聚合该时段内所有工具的总 Token

**关联史诗：** EPIC-01

#### FR-007: [MUST] 消耗明细表

**描述：** 以可切换维度的数据表格展示消耗详情数据。

**验收标准：**

- 支持按日、按模型两种查看维度切换
- 表格至少包含：名称、消耗 Token 数、费用、占比（含进度条）、缓存命中率、输入 Token、输出 Token、推理 Token、会话数

**边缘场景：**

- 数据不足最大条数时展示实际条数
- 某维度数据全部为 0 时展示空表格，不报错

**关联史诗：** EPIC-01

#### FR-008: [SHOULD] Token 消耗海报生成

**描述：** 用户可将当前区间的 Token 消耗数据生成一张竖版 PNG 海报图片，用于社交分享。海报生成和下载全部在客户端完成，不上传任何数据。

**验收标准：**

- 操作栏提供"导出海报"入口，打开海报预览弹窗
- 提供 1 套视觉模板（暗色主题风格）
- 海报内容包含：
  - 品牌标识与"TrustTools 消耗战报"标题
  - 统计区间标签
  - 消耗称号（根据 Token 总量自动判定）
  - Token 总量大数字 + 环比箭头
  - 指标三格：花费、缓存节省、缓存命中率
  - 消耗趋势柱状图（区间内各数据点）
  - 工具占比水平堆叠条 + 图例
  - Top 模型排名（最多 3 个）
  - 页脚品牌信息与分享话题标签
- 称号根据区间 Token 消耗总量自动判定，5 个等级阈值：
  - ≥ 20,000,000 → "Token 焚烧炉"
  - ≥ 5,000,000 → "重度炼丹师"
  - ≥ 1,000,000 → "百万级玩家"
  - ≥ 200,000 → "稳健通勤者"
  - < 200,000 → "克制主义者"
- 支持"下载 PNG"按钮保存到本地，文件名包含时间戳
- 支持"重新生成"按钮刷新预览
- 海报竖版尺寸（约 1080×1920 比例）

**数据边界：**

- 仅展示检测到有数据的工具，最多展示前几个
- Top 模型最多展示前 3 个

**边缘场景：**

- 无可展示数据时禁用"导出海报"按钮
- 某工具数据为 0 时跳过该工具展示

**关联史诗：** EPIC-01

#### FR-009: [MUST] 数据来源探测与状态展示

**描述：** 用户可查看本地各 AI 工具的安装探测状态和日志采集情况。这是 Token 采集的数据基础，作为独立页面，从侧边导航「数据来源」入口和首页大盘"本地 Skill 总数"卡片均可进入。

**验收标准：**

- 展示 27 个工具的探测状态，分三种：
  - **有数据**：已检测到工具且成功采集到日志
  - **无日志**：已检测到工具已安装但无日志产出
  - **未安装**：未在本地检测到该工具
- 每个工具展示：名称、状态指示、最近扫描时间
- 有数据的工具展示：采集事件数、异常行数（如有）
- 提供搜索框支持按工具名称筛选
- 提供按状态筛选的能力（全部 / 有数据 / 无日志 / 未安装），每项显示对应数量
- 提供重新扫描按钮，扫描后有完成反馈并更新时间戳，扫描期间按钮有加载态
- 顶部汇总：已接入工具数/总探测数、采集事件总数、未采集工具数、异常行数
- 未安装的工具提供下载安装引导入口
- 页面标题显示标题"数据来源" + 副标题含生成时间

**数据边界：**

- 27 个 AI 工具：Claude Code、Codex CLI、Cursor、Kiro、Gemini CLI、OpenCode、OpenClaw、Every Code、Hermes Agent、GitHub Copilot、Kimi Code、oh-my-pi、CodeBuddy、WorkBuddy、Grok Build、Kilo CLI、Kilo Code、Antigravity、pi、Craft Agents、Roo Code、Zed Agent、Goose、Droid、Mimo Code、ZCode、AnythingLLM Desktop
- 状态判定逻辑：
  - 有数据 = 检测到工具进程/安装目录 + 发现日志文件
  - 无日志 = 检测到工具但无日志产出
  - 未安装 = 未检测到
- 事件计数 = 成功解析的 Token 消耗记录条数

## 7. 数据边界定义

### 7.1 Token 消费数据

- **来源：** 本地 AI 工具日志文件，通过文件系统扫描读取
- **采集范围：** 27 个 AI 工具（Claude Code、Codex CLI、Cursor、Kiro、Gemini CLI、OpenCode、OpenClaw、Every Code、Hermes Agent、GitHub Copilot、Kimi Code、oh-my-pi、CodeBuddy、WorkBuddy、Grok Build、Kilo CLI、Kilo Code、Antigravity、pi、Craft Agents、Roo Code、Zed Agent、Goose、Droid、Mimo Code、ZCode、AnythingLLM Desktop）
- **核心字段：** 时间戳、工具名、模型名、输入 Token 数、输出 Token 数、缓存读 Token 数、缓存写 Token 数、推理 Token 数、会话数、上下文类型（Message/Tool/Reasoning/MCP/Skill）
  - 推理 Token = 模型内部推理过程消耗的 Token（区别于输入/输出），来源为 AI 工具日志中的 reasoning/thinking 字段
  - 会话数 = 该聚合区间内独立 session_id 的去重计数
- **聚合规则：** 按小时/日/周/月聚合，Token 数求和
- **不采集的字段：** 完整对话内容、prompt 文本、response 文本、文件名、项目具体代码
- **存储位置：** 本地磁盘，不上传任何云端

### 7.2 费用换算数据

- **输入：** Token 数（按模型维度）+ 模型单价表
- **计算：** 输入 Token × 输入单价 + 输出 Token × 输出单价 + 缓存读 Token × 缓存读单价 + 缓存写 Token × 缓存写单价
- **货币：** 仅人民币（CNY），精确到分
- **定价来源：** LiteLLM 模型定价数据，本地缓存，启动时检查更新
- **环比：** (当前区间值 − 上个等长区间值) / 上个等长区间值 × 100%

### 7.3 Skill 数据

- **扫描范围：** 27 个 AI 工具的 skill 目录
- **识别内容：** Skill 名称、描述、来源路径、安装时间
- **不采集：** Skill 完整内容（仅在安全检测时读取）、Skill 调用次数及调用行为

### 7.4 安全检测数据

- **输入：** SKILL.md 文件或包含 SKILL.md 的目录
- **处理：** 本地静态规则扫描，不上传源码
- **维度：** 11 个安全维度，纯静态规则匹配
- **限额：** 每天 10 次，0:00 重置

### 7.5 会话数据

- **扫描范围：** 27 个 AI 工具的会话记录
- **识别内容：** 会话 ID、标题、项目名、模型名、开始时间、时长、Token 数、轮次、工作目录
- **不采集：** 完整对话内容

### 7.6 海报数据

- **输入：** 当前页面的 Token 统计数据（区间合计、趋势点、工具占比、Top 模型）
- **处理：** 客户端本地渲染，不经过任何服务端
- **输出：** 竖版 PNG 文件（约 1080×1920 比例），存储至用户选择的本地路径

## 14. 附录 A：术语表

| 术语                    | 定义                                                        |
| ----------------------- | ----------------------------------------------------------- |
| Token                   | AI 模型处理文本的最小单位                                   |
| Provider                | AI 模型提供商，如 Anthropic、OpenAI、DeepSeek               |
| Agent / AI 工具         | 用户本地安装的 AI 编码工具，如 Claude Code、Cursor、Codex   |
| Skill                   | 一个可复用的 AI 提示词/工具包，以 SKILL.md 文件形式存储     |
| 缓存命中 (Cache Hit)    | AI 模型复用之前计算过的结果，计费通常比原价低               |
| TrustTools Web Skill 库 | TrustTools SkillPackage 提供的公开 Skill 搜索引擎和下载服务 |
| Clean Room              | 参考开源项目的架构思路但不直接复制其源码的开发方式          |
| Toast                   | 短暂弹出的操作结果通知                                      |
| 环比                    | 当前区间值与上一个等长区间值的比较                          |
