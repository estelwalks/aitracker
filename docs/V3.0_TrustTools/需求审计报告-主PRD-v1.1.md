## 关键问题（阻塞，修复后可达 PASS）

### K1: FR-005 过度依赖外部项目引用

```markdown
具体层级结构、维度划分、展开逻辑按照 TokenTracker 的实现。
```

这是不完整的需求定义。外部项目可能变化，评审者和开发者无法直接从 PRD 理解需求。PRD 层面应给出自包含的规范。

**修复建议：** 至少定义到第二层结构（如 Messages / Tool Calls / Reasoning / MCP / Skill 各维度的含义和展开路径），TokenTracker 仅作为参考标注。

---

### K2: FR-007 表格字段数据边界缺失

FR-007 表格列包含"推理 Token"和"会话数"，但 Section 7.1 核心字段仅定义了"输入 Token、输出 Token、缓存读、缓存写"，上下文类型列表为"Message/Tool/Reasoning/MCP/Skill"。缺少：
- "推理 Token"的数据来源和计算口径
- "会话数"的定义（按 session_id 去重？按对话轮次？）

**修复建议：** Section 7.1 补充这两个字段的定义、数据来源和聚合规则。

---

### K3: 缺失数据导出功能

产品哲学强调"个人 AI 主权"，Section 2.2 定位为"把数据统一收回用户手里"。但 PRD 完全没有数据导出需求。数据主权包含数据可移植性——用户应能把自己的 token 消耗数据带走。

**修复建议：** 新增 1 条 SHOULD 级别 FR：导出 Token 消耗数据为 CSV/JSON。

---

### K4: 缺失版本更新检测

Section 12 将"版本自动更新"放入范围外（V1.1），但"检测到新版本并通知用户"和"自动下载安装更新"是两回事。FR-029 设置页已有"检查更新按钮"，但缺少对应的 FR 定义其行为（主动检查 vs 启动时自动检查、通知方式、检查失败的降级）。

**修复建议：** 新增 1 条 SHOULD 级别 FR：启动时自动检查新版本，有更新时在设置页显示红点提示，点击查看版本号与 changelog（不自动下载）。

---

### K5: 缺失磁盘空间管理

本地数据持续积累（Token 日志、扫描缓存、Skill 市场缓存），PRD 未定义数据保留策略、清理机制或存储上限。NFR 没有存储相关指标。

**修复建议：** NFR 补充存储上限指标（如数据目录 < 500MB），FR-029 补充"清理旧数据"入口（如保留近 90 天数据，超出自定清理）。

## 警告（建议修复，不阻塞）

### W1: FR-011 / STORY-011 缺口未在正文说明

FR 从 010 跳到 012，STORY 从 10 跳到 12。修订记录说明了"FR-011 移入范围外"，但文档正文没有任何标注。新读者会遇到 ID 跳跃。

**修复建议：** Section 4 和 Section 6 开头各加一行 `> FR-011（原预算预警需求）已移至范围外，详见 Section 12。`

---

### W2: "数据来源"页面层级关系模糊

FR-009 归属 EPIC-01（首页大盘），描述中说"在首页大盘中提供入口或在独立页面中展示"。但 FR-027 将"数据来源"列为与"首页大盘"平级的独立导航项。到底是首页子页面还是独立模块？

**修复建议：** 统一明确：若为独立页面，FR-009 的归属应从 EPIC-01 移出；若为首页子页面，FR-027 导航中应作为二级入口。

---

### W3: FR-031 关闭行为与 macOS HIG 冲突

FR-031 规定"点击主窗口关闭按钮时，窗口隐藏（最小化到托盘），应用继续在后台运行"。这与 macOS 用户预期（红色关闭按钮 = 退出应用）冲突。许多 macOS 应用因这个设计被用户投诉。

**修复建议：** 补充说明：首次点击关闭按钮时弹出提示"TrustTools 将继续在菜单栏运行"，用户可选择"不再提示"。或改为：关闭按钮行为可配置（退出 vs 最小化到托盘）。

---

### W4: FR-003 环比在"全部"区间未定义

FR-003 数据边界："环比 = (当前区间值 − 上个等长区间值) / 上个等长区间值 × 100%"。但"全部"时间区间没有"上个等长区间"，环比值未定义。

**修复建议：** 补充："全部"区间不展示环比，或改用"月均"作为替代指标。

---

### W5: FR-018"更新规则库"与范围外"版本自动更新"概念交叉

FR-018 提供"更新规则库"按钮，规则库"随软件版本发布，版本号与软件版本一致"。但 Section 12 将"版本自动更新"放入范围外（V1.1）。如果规则库只能随软件版本更新，那"更新规则库"按钮的唯一作用就是触发软件版本更新——这在范围外。

**修复建议：** 二选一：(a) 规则库独立于软件版本，可通过网络拉取最新规则（需补充数据来源、更新频率、失败降级）；(b) 移除"更新规则库"按钮，改为展示当前规则库版本号（来自软件版本），规则更新=软件更新放在 V1.1。

---

### W6: 缺失首次启动引导

PRD 多处定义了空状态（未检测到 AI 工具时的引导页、未扫描到 Skill 时的空状态），但没有定义首次启动的 onboarding 流程：用户打开应用后看到的第一个画面是什么？是否需要欢迎页/功能简介/权限申请？

**修复建议：** FR-013 补充首次启动引导：展示产品简介（一句话定位 + 3 个核心能力图标），引导用户开始首次扫描。

---

### W7: 缺失应用升级安装行为

FR-030 定义了卸载行为（.app 与数据分离），但未定义升级安装行为：用户下载新版本 .dmg 覆盖安装时，旧版本数据是否兼容？是否需要数据迁移？

**修复建议：** FR-030 补充：升级安装时自动检测 `~/.trusttools/` 数据兼容性，不兼容时提示用户备份后清除。

| 张力 | 说明 |

| 指标 | 基线 | 目标 | 可测量性 |
|------|------|------|----------|
| 安装后 2 分钟内看到 token 消耗 | 无 | < 2 分钟 | ✅ 可测量 |

### 5d. NFR 优先级一致性

NFR-001~008（性能）未标注 MUST/SHOULD 优先级。建议补充，至少标注 NFR-001（首页加载 < 2s）和 NFR-005（首次安装 < 2min 看到数据）为 MUST。
