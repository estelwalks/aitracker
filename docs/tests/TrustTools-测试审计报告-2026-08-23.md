## Findings

### P1（已关闭）：核心 E2E 缺少可执行浏览器证据

- 覆盖点：全系统路由、设置、语言/货币和关键交互。
- 重要性：单元测试与 SSR 构建无法证明浏览器 hydration 和用户交互正常。
- 证据：隔离 E2E 共 38 项均在 `browserType.launch` 前失败，原因是 Playwright Chromium 缺失；安装进程长时间无输出后终止，没有任何业务断言实际运行。
- 关闭证据：使用本机 Google Chrome 与隔离 Home 配置实际执行浏览器断言，核心套件 38/38 通过。CI 仍应固化匹配版本的 Chromium。

### P1（已关闭）：首屏共享 JavaScript 超过预算

- 覆盖点：启动性能与弱设备体验。
- 重要性：首屏共享 bundle 过大可能导致桌面/Web 首次加载和 hydration 变慢。
- 证据：`verify:bundle-budget` 报告 initial shared gzip 395,765B，预算 256,000B；超出 139,765B（54.6%）。
- 关闭证据：修正门禁对 Vite preload 映射的误计数，将完整语言包改为按 locale 动态加载，并以轻量路由元信息词典替代路由对完整词典的静态依赖。复测 initial shared gzip 172,771B < 256,000B，最大懒路由 37,698B < 122,880B。

### P2：原 97 条产品用例与当前模块结构脱节

- 覆盖点：reports、distill、sources、tracker、widget、任务编排、AI insight 等当前能力。
- 重要性：大量用例不等于覆盖当前风险；缺少需求—风险—自动化 ID 的可追溯关系会降低发布信心。
- 证据：原文档只按 6 个模块组织，而模块目录门禁识别 17 个模块，E2E 已覆盖 13+ 路由。
- 修订：以当前模块目录为基线维护 traceability matrix，并给每个 P0/P1 风险绑定自动化文件/用例名。

### P2：桌面原生与恢复演练证据仍偏静态

- 覆盖点：macOS 托盘、窗口生命周期、签名/打包、升级安装、真实恢复演练。
- 重要性：Electron 单测和编译通过不等于签名包可安装、托盘和升级数据真实可用。
- 证据：本轮 `build:electron` 通过，数据库恢复单测通过，但未执行 DMG 打包、签名安装、升级与实体桌面交互。
- 修订：发布候选包在 macOS 实机执行安装/升级/托盘/Cmd+Q/恢复清单并保存截图或日志。

### P2：可观测性与告警验证缺少端到端证据

- 覆盖点：失败事件、后台任务、告警确认/恢复。
- 重要性：单元层能证明规则，但不能证明用户最终看见正确状态与诊断信息。
- 证据：monitoring 与 task 单测覆盖事件和状态机，产品测试方案缺少从故障注入到 UI 告警的完整路径。
- 修订：增加采集超时、SQLite 写失败、市场离线和模型超时的故障注入 E2E。

## 审计假设

- 当前未提交代码代表用户希望验证的候选状态，不回退或覆盖其功能改动。
- 本地开发应用无登录要求，因此系统 URL/用户名密码不适用。
- 外部市场与真实模型服务不作为离线自动化的强依赖。

## 剩余发布风险

两个 P1 发布阻断风险均已关闭。桌面实体机安装/升级/签名与故障注入告警 E2E 仍属中等残余风险，应在发布候选包人工验收阶段处理。

## 总体信心摘要

代码级、数据安全、核心浏览器路径与首屏体积信心高。建议状态：**自动化质量门禁放行，进入发布候选包人工验收**。
