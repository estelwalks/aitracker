## 1. 请求摘要

**当前要做什么**：TrustTools 已完成「确定性 mock 原型」阶段——13 个页面、三主线五载体小组件、中英日三语、32 Agent 目录均已落地，PRD（`trusttools-产品需求文档.md` v4.4）已闭环。下一步是从「mock 原型」转向「可接真实数据的产品」，需要一份把散落上下文收敛成单一事实来源的工程简报，让下游 skill（架构设计 / 技术选型）无需反复回读原始文档。

**要解决的业务/交付问题**：TrustTools 定位 to C 爆款（装机量 10 万级，先不挣钱）。旧版「只有统计、不性感」已被推翻，现以「AI Agent 主权控制台」为定位，三条主线（安全 / 高效 / 蒸馏）贯穿。原型阶段已证明视觉与信息架构成立，但**真实数据采集、macOS 原生客户端、运行时安全**等均未接真，是通往可落地版本的核心缺口。

---

## 2. 业务目标

**主要目标**：
1. **装机量 10 万级**（首要目标，先不挣钱）——冷启动关键，GitHub 首版质量决定能否起量。
2. **三条价值主线**，必须在一级菜单体现：
   - **安全**：让人安全地用 AI（静态定时扫描 + 运行时安全）
   - **高效**：人机协同效率诊断（谁高效、谁浪费 → Token 燃烧榜）
   - **蒸馏**：把过程沉淀为私有资产（Skill / 工作流 / Prompt / 角色 / 画像 / 任务记忆）

**成功信号**（对应 PRD §9 KPI，基线待定）：

| 维度 | 指标 | 目标方向 |
|---|---|---|
| 装机 | 下载 → 激活转化率 | 装机量 10 万级 |
| 留存 | 次周留存率 | 待定基线 |
| 蒸馏 | 周活跃蒸馏用户占比 / 人均蒸馏产物数 | 提升 |
| 安全 | 安全扫描覆盖率 / 拦截可疑 Skill 数 | 覆盖 100% 本地 Skill |
| 高效 | 燃烧榜识别并优化的浪费占比 | 提升 |

**失败后果**：① 视觉不性感 → 冷启动失败（视觉是生死线）；② 安全信任缺失 → 用户弃用（安全是「第一主线」）；③ 私有上下文无法沉淀 → 留存崩塌（蒸馏是留存关键）。

## 3. 范围

### 范围内（P0 + P1，已实现或 Web 原型已验证）

- **13 个页面**：首页 `/`、Agent 概览 `/agents`、蒸馏 `/distill`、日报周报月报 `/reports`、记忆库 `/memory`、安全检测 `/security`、燃烧榜 `/tracker`、Skill Hub `/skills`、安全市场 `/market`、会话管理 `/chats`、菜单栏小组件 `/widget`、设置 `/settings`、数据来源 `/sources`。
- **三主线 × 五载体小组件**（Web 设计稿）：菜单栏灵动岛 / 浮窗三 Tab / 托盘 / 桌面小·中·大三档。
- **蒸馏 6 产物**：Skill / 工作流 / Prompt / 角色 / 画像 / 任务记忆（「角色」当前未落库，归记忆库联动补充）。
- **记忆库**：独立一级页面，列表 / 增删改 / 蒸馏自动写入。
- **安全市场 `/market`**：仅收录通过 11 维安全扫描的 Skill，一键分发到本地 Agent。
- **中英日三语**：zh/en/ja 主词典 + 扩展词典，缺 key 回退中文。
- **32 Agent 目录**（13 有数据 / 7 已发现 / 12 未发现）。

### 范围外（WON'T，见 PRD §7）

1. 桌面组件内管理动作（只读，一律跳转对应页面）
2. **macOS 原生客户端**（Swift / AppKit / WidgetKit / NSStatusItem 常驻）——P2
3. **一键迁移**（远期主打粘性）——P2
4. **MCP 管理独立路由**（增删改）——首版不做，`mcpServers` 仅 mock
5. **运行时安全**（真实会话执行前检查）——当前 mock 占位
6. **Agent 扩到 38+**（国内主流：豆包/通义/Cherry Studio/LobeChat 等）——P2
7. 市场真实远端拉取 / 支付 / 企业私有源
8. Windows 原生客户端（首版不做，后续简单适配）
9. 记忆「注入回会话」完整机制（本次只做存储与管理）

## 4. 角色与关键场景

### 角色

| 画像 | 特征 | 核心诉求 |
|---|---|---|
| **AI 重度开发者**（主） | 同时装 5+ AI 编码工具，每天烧大量 Token | 谁在浪费钱/Token、Skill 是否安全、好上下文能否沉淀复用 |
| **AI 尝鲜者 / 极客**（次） | 关注装逼属性、社区传播、视觉冲击 | 「会说话的贾维斯」常驻桌面/菜单栏，滚动播报、锁屏可见 |

### 主要流程

1. **安全巡检**：定时/手动静态扫描本地 Skill → 11 维度体检 → 展示安全/可疑/高风险 → 查看单 Skill 报告 → 隔离/处置。
2. **知识蒸馏**：选原材料（会话/项目 或 Agent 提示词/配置）→ 选 6 种产物 → 补附加指令 → 生成 → 能力资产走文件树导出/安装，记忆资产自动落库。
3. **日报生成**：AI 依据周期会话自动生成 Markdown → 编辑/预览 → 保存（30s 自动存档）/ 导出 PDF / 复制。
4. **浪费诊断**：燃烧榜三维（项目/会话/Skill）→ 看浪费占比与可读原因 → 按优化建议行动。
5. **市场安装**：安全市场检索 → 仅收录扫描通过的 Skill → 勾选目标 Agent → 一键安装/卸载（`trusttools install <name>`）。
6. **小组件常驻**：菜单栏灵动岛循环播报安全/浪费/缓存/可蒸馏/Token 信号。

### 关键边缘流程

- 无会话数据空态（蒸馏/日报/燃烧榜）
- 市场无匹配 Skill、离线状态（本地缓存可浏览）
- 蒸馏配额耗尽（提示切换模型）
- 重新生成日报需二次确认覆盖已编辑内容
- localStorage 损坏/隐私模式写失败（try/catch 回退种子数据）
- 未发现客户端的 Agent 不作为安装目标

## 5. 非功能需求

> 原型阶段无服务端、无并发压力；以下沿用 PRD §3 NFR，并标注「待确认」的缺口。

| 类别 | 要求 | 状态 |
|---|---|---|
| 性能 | 首页首屏与组件交互 2s 内可感知；确定性 mock 渲染稳定无抖动 | 已满足（mock） |
| 安全与隐私 | 所有数据写本地（localStorage / 本地目录），不上传云端；API Key 脱敏；清除数据二次确认；隐私条全程可见 | 核心约束 |
| 可维护性 | 聚合逻辑下沉 lib、页面只消费结果；组件超 200 行拆分；错误统一 toast + 日志 | 已约定 |
| 可扩展性 | 数据源配置化（`sources.ts` catalog），新增 Agent 仅补目录与下载地址 | 32 → 目标 ≥38 |
| 视觉一致性 | 全站统一设计 token；状态用中性标记（亮度 + 呼吸，不高饱和告警色）；Apple 设计语言 | 已约定（NFR-001 已补量化验收） |
| 实时性 | 小组件信号「即时反映」，菜单栏轮播按配置间隔自动切换 | Web 侧已约定；常驻/锁屏可见依赖原生 P2 |
| 规模 / 并发 | 单用户本地应用，无并发/吞吐压力 | **多设备同步是否需支持：未知，待确认** |
| 可用性 / 恢复 | 常驻服务「不打开也在跑，锁屏可见」 | **假设，依赖原生客户端（P2），待确认** |

## 6. 约束与依赖

- **技术栈**（现原型）：Vite + React 19 + TanStack Start/Router（file-based routes）+ Tailwind v4 + TypeScript + bun。
- **平台**：macOS 优先，Windows 后置简单适配。
- **竞品对标**：TokenTracker——架构为菜单栏 NSStatusItem + WKWebView 浮窗 + WidgetKit 桌面组件；视觉学 Apple，注入「贾维斯人格」为超越点。
- **数据源**：本地 AI Agent 会话留存（Claude Code / Codex / Cursor 等），采集口径见独立文档《`trusttools-数据采集规范.md`》（来源 → 获取方式 → 数据类型）。
- **确定性 mock 架构**（勿混用两套哈希）：`hashS` 多项式（agent-view/sources/skill-scan 等）vs FNV-1a（mock-data/chats）；统一 `rnd(seed,max)=hash(seed)%max`。真实数据接入时只替换 `rnd`，聚合/缩放/占比逻辑不变。
- **代码依赖**：`sources.ts` catalog（Agent 目录）、`skill-files.ts`（Skill 目录约定）、`context-engine.ts`（Token 上下文计算引擎，**非**记忆回注）、`agent-view.ts`（securityPulse/roastList/usageMetrics）、`widget-metrics.ts`、`quota.ts`、`memory-store.ts`、`distill-history.ts`。
- **团队 / 时间**：2 人全职，2–3 周出可落地版本（**来自会议纪要，假设，见 §7**）。

## 8. 待确认问题

### 设计前必须确认（实质影响架构 / 测试策略）

1. **macOS 原生客户端技术栈**：Swift/AppKit/WidgetKit 原生 vs Tauri/WKWebView 复用现有 Web 设计稿——决定 UI 复用度与「单套 Web 代码 vs 双端代码」。
2. **真实数据采集架构**：如何本地解析各 Agent 会话日志；统一适配层 vs 逐工具适配（5–6 核心工具深度）。
3. **「AI 流式总结 / 日报草稿」的生成模型**：本地模型 vs 远程 API——决定是否引入后端、API Key 管理、成本与隐私边界。
4. **多设备同步**：localStorage 单机 vs iCloud/远端同步——决定数据层是否需服务端。

### 可延后但需跟踪

5. 运行时安全（会话执行前检查）真实实现边界（P2，但影响「安全」主线闭环）。
6. 记忆「注入回会话」机制（当前只做存储管理）。
7. 一键迁移工具对（Claude Code ↔ Codex ↔ DeepSeek Coder）。
8. Agent 38+ 覆盖清单（豆包 / 通义 / Cherry Studio / LobeChat 等）。
