## 1. 背景与目标

以 `docs/V3.0_TrustTools/project-sparkle-hub-92-33a292ea-main` 的首页总览（`/`）、工具概览（`/agents`）、数据来源（`/sources`）和侧栏导航为视觉与交互参照，将当前 V3.0 应用重构为可由本地真实采集数据驱动的模块化驾驶舱。展示层必须保持原型的洞察→筛选→指标→趋势/明细的信息层级，不得以模拟数据填充生产视图。

## 2. 功能范围

### 2.1 首页总览（/）

- 今日洞察、监听状态条及工具/安全/蒸馏/今日消耗聚焦卡；洞察可轮换。
- 统一时间范围（今天、7 天、30 天、全部、自定义）和工具筛选；所有卡片、图表、表格共享同一范围。
- 八项指标：Token、费用估算、会话、缓存命中、活跃工具、安全、Skill 资产、项目数。
- Token 趋势、模型消耗、项目消耗与 12 个月活跃日历；不可得数据明确显示“不可用”，不合成零值。

### 2.2 工具概览（/agents）

- 工具专属洞察、工具覆盖状态和可切换的工具卡墙。
- 所选工具的趋势、上下文构成、模型/项目明细和安全摘要。
- 下方保留现有 Skill 工作台：扫描、筛选、同步、卸载等行为继续通过现有受控服务端接口执行。

### 2.3 非范围

- 不读取或向浏览器暴露原始对话、提示词、命令、绝对路径或密钥。
- 不因 UI 展示而触发本地安全扫描或写入采集源。

### 2.4 Dashboard 原型结构与真实行为

- 首页按原型重组为 `JarvisInsight`、`TrustHero`、原型 RangePicker、ToolSwitcher chip、TokenTrendPanel、ModelDonut、ProjectOverview、ContribHeatmap 和选中工具后的 AgentWorkstreams；所有卡片、tooltip、delta 与图例从同一时间/工具筛选投影读取。
- JarvisInsight 首选显示受配置 LLM 生成的真实洞察；配置缺失、数据不足、超时或校验失败时显示规则洞察或“LLM 未配置/不可用”状态，不得显示 mock 文案。
- TrustHero 的活跃工具、安全扫描、知识/蒸馏资产与 Token 消耗必须分别标记来源和可用性；安全、蒸馏、日报没有真实历史时显示不可用，不得由 Token 推算。
- 趋势使用真实日粒度 cache/net input、会话及可比上一周期数据；模型、项目、热图和 AgentWorkstreams 仅使用真实聚合，数据不足时保留原型布局并展示空态。

### 2.5 Sources 与导航原型对齐

- Sources 页采用原型 PageBar、4 项指标、搜索/筛选 chip 和双列工具卡。卡片展示真实安装/日志状态、事件、异常行、读取进度、绑定 Skill 数、最后扫描时间、工具类型、`~/` 相对扫描目录和官方下载链接。
- “一键迁移”保留原型位置，但当前必须禁用并说明“工具未提供可验证的安全迁移格式”；现有蒸馏工作流仍是唯一真实的知识沉淀入口。不得以 toast 或下载伪装已完成跨工具上下文迁移。
- 侧栏改为原型的 React 状态折叠、窄屏响应和蒸馏高亮风格；主导航使用 `/chats` 和 `/tracker`，原 `/sessions`、`/market` 保持兼容入口。

## 3. 数据需求与获取方式

| 维度                            | 权威来源                               | 获取/计算方式                                              | 不可用策略                                 |
| ------------------------------- | -------------------------------------- | ---------------------------------------------------------- | ------------------------------------------ |
| Token、模型、项目、趋势、上下文 | `DashboardV2Snapshot.events`           | 本地使用事件按时间、工具、模型、项目聚合                   | 空集显示无活动                             |
| 费用                            | 定价规则与使用事件                     | `estimateUsageCost` 聚合已知/估算费率                      | 未配置定价显示不可用，部分价格标注部分估算 |
| 会话                            | `sessions.bySourceDay`、`byProjectDay` | 在同一时间区间累加                                         | `sessions.available=false` 时显示不可用    |
| 缓存命中                        | 输入、缓存输入、缓存创建输入           | `cachedInput / (input + cachedInput + cacheCreationInput)` | 分母为 0 时显示不可用                      |
| 工具状态                        | `snapshot.tools` 和近期事件            | 活跃事件优先；再依次为已检测、可用、不可用                 | 保持目录状态                               |
| 监听与安全                      | `MonitoringStatus`                     | 仅消费聚合计数、心跳和健康态                               | 无监控状态显示不可用                       |
| Skill 资产                      | 本地 Skill 扫描快照                    | 服务端扫描并投影为浏览器安全 DTO                           | 扫描失败保留最近快照并提示                 |
| LLM 洞察                        | 脱敏 Dashboard 聚合 + 配置的 LLM       | 显式刷新或 TTL 缓存下调用服务端 OpenAI 兼容 Chat 接口      | 未配置/失败显示状态或规则洞察，不伪造结果  |

### 3.1 LLM 洞察隐私与运行约束

- 仅允许服务端读取 `TRUSTTOOLS_LLM_BASE_URL`、`TRUSTTOOLS_LLM_API_KEY`、`TRUSTTOOLS_LLM_MODEL`；密钥、请求头、原始 prompt 和 provider 响应元数据不得进入浏览器、日志或下载包。配置即代表用户选择该服务商并允许发送下述匿名聚合。
- 请求体只能包含时间范围、Token/费用/缓存/会话/模型/项目/工具/安全/蒸馏/日报等已脱敏聚合；禁止传递原始会话、消息、命令参数、完整路径、Skill 正文和可恢复 session ID。
- LLM 输出必须通过长度、结构和敏感字段校验；只允许显示洞察正文、生成时间、模型标识和状态。刷新动作有超时、预算和 TTL 缓存保护。
- 用户未配置任何 LLM 时，不产生网络请求；规则洞察仍必须可追溯到本地真实聚合。

### 3.1 数据证据状态

每个展示字段必须携带或可推导其证据状态，页面不得把缺失值格式化为 `0`：

- `observed`：日志中存在该字段；值可为真实零。
- `unavailable`：工具已安装或有日志，但该字段无法从当前 schema 获取。
- `unsupported`：尚无对应 reader。
- `not-installed`：本机未发现安装证据。
- `estimated` / `partial`：费用来自本地费率估算，并明确完整性。

安装状态、日志发现、Usage 支持和 Session 支持是四个独立维度。安装探测同时使用候选目录与可执行文件证据；合成 session id 不得展示为可恢复会话。

### 3.3 实机数据修复要求

- Claude Session 按 `(sessionId, message.id)` 去重 usage，Token 总量必须与 Usage reader 同口径对账。
- Codex Session 正确读取 `session_meta` / `turn_context` 的 `payload`，识别 `exec` 命令与 `patch_apply_end` 编辑事件。
- reasoning 若是 output 子集，不得再次加到总 Token；上下文构成必须使用互斥分类。
- 项目、模型总数独立于 Top-N 行数；自然日均必须补齐无事件日期。
- “文本回复/用量事件/估算费用/使用活跃日”等标签必须如实描述口径。

## 4. 验收标准

- 两页在 1440px 与窄屏下保持原型的卡片层级、工具选择、洞察轮换和详情切换交互。
- 切换时间范围或工具后，相关指标、趋势、模型、项目、会话及上下文使用同一聚合结果。
- 任一缺失来源不得显示伪造数字；安全、会话、费用、缓存分别独立降级。
- Claude 与 Codex 的 Usage/Session 对账测试通过；已安装工具的字段缺失以“不可用”展示。
- 工具概览的选择状态、趋势时间范围、模型/项目 Tab 可操作，Skill 工作台的原有管理行为不回归。
