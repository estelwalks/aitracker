## 背景

TrustTools 当前的安全评估使用浏览器端静态规则扫描，只覆盖 `SKILL.md` 的受限输入。产品需要替换为覆盖 Skill 目录、规则复核和可选行为分析的完整扫描能力，同时保持扫描器可以独立演进并由主项目按版本升级。

## 决策

- 独立源码仓库名为 `skill-scanner`。开发期 `package.json` 使用 `name: "skill-scanner"` 与 `private: true`；公开 npm 包名、scope 和发布策略在开源发布前单独决定。
- TrustTools 在 Electron 主进程直接引入该 npm 包。扫描器不以 Python 运行时、Git 子模块或常驻 HTTP 服务的方式随应用运行。
- 包导出 `scanSkill(request)`、Zod 输入/输出 schema、规则版本和风险枚举。输入是由宿主受控读取的相对路径文件集，而不是任意本地目录路径。
- 扫描器提供 `quick` 和 `full` 两种模式：两者均执行静态规则；`full` 额外执行规则命中复核及单文件/多文件语义行为分析。Skill 中的脚本只作为文本分析，绝不执行。
- 用户在桌面端配置自己的 OpenAI 兼容模型端点、API Key 及 lite/pro 模型。完整扫描必须由用户显式开启；密钥由 Electron `safeStorage` 加密保存，渲染进程不可读取。
- 后台本地 Skill 监控仅使用 `quick` 模式；人工发起的深度扫描使用 `full` 模式。模型不可用、超时或返回无效结构时，报告标记为部分完成并保留静态结果，不得判定为安全。

## 集成边界

Electron 主进程负责目录选择、路径归一化、拒绝符号链接、文件数量/深度/大小限制和文本读取。主进程仅把通过校验的内存文件集传给 `skill-scanner` 包。

扫描器内部的行为分析工具只能读取其内存虚拟工作区。报告只保留相对路径、脱敏命中片段、风险类别、严重度、修复建议、规则/引擎版本和扫描分支状态；不得保存源码、绝对路径、API Key 或模型上下文。

现有 `src/lib/security` 扫描器、页面 DTO、历史记录和后台监控适配器将迁移到新包的报告契约。旧历史记录保留为只读 `legacy-v1` 数据，不重新映射为新引擎结论。

## 检测结果国际化

扫描请求必须携带当前应用语言 `locale`，其取值限定为 `zh-CN`、`en-US`、`ja-JP` 或 `ko-KR`。扫描器只生成该 `locale` 的标题、描述、修复建议和摘要；静态规则与 LLM 深度分析均遵循同一语言。

风险类别、规则 ID、严重度、评分、`allow|warn|block` 结论、文件相对路径和证据定位保持语言无关。报告持久化 `locale`、扫描器版本、规则版本、模式和内容哈希，使报告的语言来源可审计。

TrustTools 切换应用语言时不得把已有报告直接当作目标语言结果使用：若 `report.locale !== currentLocale`，页面标记该报告为“需要按当前语言重新检测”，并提供显式重新检测操作；不得在未确认时自动发起模型调用。新报告缓存键为 `contentHash + scannerVersion + rulesVersion + mode + locale`，不同语言的报告不互相复用。

此策略以重新检测的时间和模型成本换取更小的报告体积与更简单的实现；历史报告仍以其原生成语言只读展示，并带语言标识。

## 旧检测实现移除

`skill-scanner` 包通过基准样本、契约、IPC、隐私和 Electron 打包验收后，必须删除项目内目前的检测实现，而不是与新引擎长期并行：

- 删除 `src/lib/security` 中仅属于旧浏览器扫描器的静态规则、规则生成物、正则安全门、扫描实现及其测试；删除所有调用旧 `scanSecurityFiles` / `scanSecurityFilesWithProgress` 的生产路径。
- 删除旧检测规则配置、旧三档风险映射和仅为旧检测页面服务的进度语义；安全评估页面、后台监控和服务端适配器全部改为消费新包的 schema。
- 保留并改造非检测职责的存储、展示和配额模块；它们只能保存新包已脱敏的报告 DTO。既有报告作为 `legacy-v1` 只读展示，不触发旧扫描器，也不参与新旧结果比较。
- 切换期间允许在开发/CI 中对同一授权样本并行执行新旧引擎以验证兼容性；正式应用中不得同时发布两个检测引擎或根据旧引擎结果做风险判定。

删除条件是：新包覆盖所有当前入口、基准样本结果满足验收、模型失败降级可见、隐私测试和 Electron 打包测试通过。删除后的回滚方式是回退 TrustTools 到上一发布版本或回退 `skill-scanner` 的固定版本，不重新引入已删除的旧检测代码。

## 发布与更新

1. 在 `skill-scanner` 仓库完成规则、Prompt、引擎与测试修改，并按语义化版本发布；公开 npm 包名在发布决策完成后确定。
2. 每个版本发布变更日志、规则版本、兼容性说明、许可证、NOTICE 和依赖清单。
3. TrustTools 使用精确版本依赖；升级时更新版本与锁文件，执行契约测试、扫描黄金样本测试和 Electron 打包验证。
4. 报告 schema 的破坏性变更提升主版本，由 TrustTools 显式适配；不得通过无版本更新改变已保存历史报告的语义。

## 验收与风险

- Node 引擎对授权基准样本的类别、命中、权重、评分、风险等级和处置结论保持一致。
- CI 以 mock 模型覆盖复核、行为分析、去重、超时和格式错误，不调用真实模型 API。
- 覆盖目录越界、符号链接、超量/超大/二进制文件、恶意文件名、未配置模型和 IPC 参数篡改。
- 覆盖中、英、日、韩四种 `locale` 的静态与深度扫描输出，以及语言切换后的“需要重新检测”状态和按语言隔离的缓存键。
- 验证日志、IPC、历史记录和 UI 不泄露源码、绝对路径或密钥；验证 Electron 打包后规则和 Prompt 资源可加载。

代价是首发仅支持 Electron 桌面端，Web 运行时不提供完整深度扫描；模型分析会消耗用户自己的 API 配额，且用户明确授权后才可将 Skill 内容发送到其模型端点。

## 状态

草稿。开始 Node 包开发和 TrustTools 替换前，应完成许可与 NOTICE 落档，并由产品和技术负责人确认本 ADR。
