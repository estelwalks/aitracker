# ADR-006：架构门禁与迁移基线

## 状态

已接受（P8-02）。

## 背景

模块化迁移期间，路由瘦身、生成代码和旧模块拆分会产生一批已知边界问题。若直接把所有历史问题设置为 CI 失败，无法安全增量迁移；若始终只报告，又无法阻止新问题继续进入主干。

## 决策

`scripts/verify-module-boundaries.mjs` 提供两种模式：

- `npm run verify:architecture`：报告模式，始终返回成功，用于本地观察迁移进度。
- `npm run verify:architecture:blocking`：阻断模式。只有明确记录在脚本 `MIGRATION_ALLOWLIST` 中的既有问题可以通过；任何新增违规、白名单格式错误或未登记文件都会返回非零退出码。

迁移基线必须逐条包含 `type`、`file`、`reason`、`owner`、`expiresAtPhase`。匹配仅按违规类型和仓库相对文件路径进行，不允许通配符、永久豁免或仅按目录豁免。新增违规不能通过修改输出或扩大匹配范围绕过门禁。

当前迁移基线为空。locale/security 循环、settings presentation barrel 循环和 `__root` 根路由行数超限均已在 P8 清理完成；TanStack 生成路由图循环按 [ADR-007](./ADR-007-生成路由图循环分类.md) 分类为 generated-tooling intrinsic cycle，不进入迁移白名单。

页面采集轮询不属于迁移基线。路由中的 `setInterval` 会阻断，唯一允许的例外是明确命名为 `progressTimerRef` 的安装进度动画。

## CI 使用

CI 应执行 `npm run verify:architecture:blocking`，不要通过设置环境变量关闭门禁。迁移完成后，删除相应基线项并将脚本中报告模式升级为默认阻断；基线项到期时必须删除或提交新的 ADR 说明，不得延长为永久豁免。

## 验证

`scripts/verify-module-boundaries.test.mjs` 覆盖：

- 基线条目字段完整性；
- 新增页面采集轮询无法被基线隐藏；
- 已知基线问题被抑制；
- 已完成页面路由不再出现在迁移白名单；
- blocking 模式对剩余违规返回失败。

## 复审记录（2026-08-18，页面性能优化）

性能优化（ADR-009）扩展了门禁集合，本 ADR 的基线语义保持：

1. **架构门禁现状**：`verify:architecture:blocking` 违规数从 15 → **0**
   （settings/skill-catalog/skill-distribution 深层导入与 dashboard ai-insight
   已通过窄化 barrel 与公共入口修复，T6-02）；迁移基线仍为空。
2. **新增 browser/server boundary gate**（`verify:browser-server-boundary.mjs`，
   T6-03）：阻断 browser 图内 `node:*` builtin 与 `*.server.ts` 静态导入；
   createServerFn 定义文件豁免（它们是 RPC 端点）。
3. **新增 bundle budget gate**（`verify:bundle-budget.mjs`，T6-06）：结构性
   阻断 entry 内 server 实现 chunk；CSS ≤ 40 KB gzip；初始共享 JS 字节预算
   由固定性能环境执行（当前 219 KB gzip ≤ 250 KB）。
4. **新增 read-model budget gate**（`verify-read-model-budgets.mts`，T1-08）：
   DTO ≤ 250 KB、禁止字段、无原始事件。
5. **生成物漂移门禁**：`verify:runtime-policy.mjs` / `verify:job-catalog.mjs`
   保证策略源与生成物一致（T0-03/04）。

基线删除条件不变：迁移完成后删除对应基线项；不得通过扩大永久 allowlist
伪造通过。
