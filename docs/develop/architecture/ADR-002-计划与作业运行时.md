## 背景

本 ADR 是《AITracker 业务模块化与任务编排架构设计》及《AITracker 产品工作台重构实施计划》的 P0 决策门禁。未完成复审前，后续实现必须遵守本文件的保守边界。

## 决策

以 JobType、Schedule、JobRun 取代页面 timer 和仅刷新型任务。

## 实施约束

JobType 随包 JSON；Schedule 是受控用户状态；JobRun 持久化、single-flight、可恢复、可取消。

## 代价与放弃

应用退出后不执行；不支持用户定义任意命令或 cron。

## 复审记录（v1.1，2026-08-18）

性能优化（ADR-009）落地后，本 ADR 的约束按以下方式演进，决策本身未变：

1. **JobType 随包 JSON 的权威位置迁移**：`job-catalog.json` 已并入
   `src/app/runtime-policy.source.json` 的 `scheduledJobs`，由
   `generate-runtime-policy.mjs` 生成 `job-catalog.generated.ts`；漂移由
   `verify-runtime-policy.mjs` / `verify-job-catalog.mjs` 阻断。周期、超时、
   网络权限与资源预算在同一文件（T0-04）。
2. **快照刷新任务通过 Snapshot Coordinator 执行**：usage/sessions/skills
   的 executor 调用各领域快照 runtime 的 `refreshNow(signal)`（single-flight、
   abort-before-commit、last-known-good），而非直接构造 scanner（T2-07、
   T3-08/09）。exchange.refresh 任务刷新汇率快照。
3. **资源预算接入**：scheduler 对 collection 类任务获取全局 heavy permit
   （maxHeavyCollectors=1，来自策略），取消/失败必释放（T5-06）。
4. **默认启用**：快照刷新任务（usage/skills/sessions/exchange）默认启用，
   避免偏好缺失导致数据长期 stale（T3-10）。

复审结论：核心决策（随包定义、受控 schedule、持久化 single-flight 可恢复
JobRun）保持不变；实现细节按上述方式演进。
