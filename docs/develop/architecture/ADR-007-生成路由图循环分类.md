# ADR-007：生成路由图循环分类

## 状态

已接受（P8）

## 背景

TanStack Router 生成的 `src/routeTree.gen.ts` 会导入文件路由，并通过类型导入反向引用 `src/router.tsx`；运行时入口 `router.tsx` 又需要导入生成的 `routeTree`。这形成 `routeTree.gen.ts -> router.tsx -> routeTree.gen.ts` 的循环。

该循环由生成器和框架注册协议产生，不代表业务模块之间的依赖倒置，也无法通过手工修改生成文件稳定消除（下一次生成会恢复）。

## 决策

架构门禁将同时包含 `src/routeTree.gen.ts` 与 `src/router.tsx` 的循环分类为 `generated-tooling intrinsic cycle`：

- 不进入业务循环违规列表；
- 不使用临时 `MIGRATION_ALLOWLIST` 条目掩盖；
- 在报告中单独显示计数，持续证明该分类仍存在；
- 生成文件继续由 TanStack Router 管理，不手工编辑或改变生成器行为。

其它循环仍按 `relative-import-cycle` 检查，并必须通过模块边界重构或有期限的迁移基线处理。

## 影响

门禁不会因框架固有循环阻断发布，同时仍能发现新增的业务循环。若未来升级生成器消除了该循环，分类计数应自动归零；若生成器改变入口文件，应同步更新 `isGeneratedToolingCycle` 的明确路径判定和测试。
